本ドキュメントは、各画面の表示項目、具体的な権限・参照範囲、ボタン表示条件、入力・操作時のバリデーション、画面内フィードバックを定義する。

## 3. 共通レイアウト・メニュー制御

### 3-1. サイドバー

| メニュー | 表示ロール | 遷移先 |
|----------|------------|--------|
| ダッシュボード | 全ロール | SC-01 |
| ドメイン台帳 | 全ロール | SC-02 |
| ドメイン登録 | システム管理者、ドメイン管理担当者、利用部門 | SC-04 |
| 棚卸 | システム管理者、ドメイン管理責任者・担当者、利用部門 | SC-08 |
| セキュリティ・リスク | システム管理者、セキュリティ運用、DNS・インフラ運用、管理責任者・担当者 | SC-10 |
| 証明書 | システム管理者、セキュリティ運用、DNS・インフラ運用、管理責任者・担当者 | SC-12 |
| 監視対象 | システム管理者、知財・ブランド管理、管理責任者・担当者 | SC-14 |
| インシデント | システム管理者、セキュリティ運用、管理責任者・担当者 | SC-16 |
| 変更履歴 | 全ロール | SC-18 |
| 承認 | システム管理者、ドメイン管理責任者、知財・ブランド管理 | SC-20 |
| マスタ・権限管理 | システム管理者 | SC-22 |
| 利用方法 | 全ロール | SC-23 |

- 権限がないメニューは表示しない。
- URL 直アクセス時に権限がない場合は 403 を返す。
- 承認、棚卸、リスクの各メニューには、未対応件数バッジを表示する。
- htmx 操作後（承認・棚卸回答・是正完了等）は、該当バッジを OOB 更新する。

### 3-2. 共通ステータス表示

#### ドメイン状態

| 状態 | ラベル | 表示方針 |
|------|--------|----------|
| `active` | 利用中 | 成功色 |
| `pending` | 承認待ち | 警告色。承認対象として表示 |
| `expired` | 失効 | 危険色 |
| `deleted` | 廃止済み | グレー。通常一覧から除外 |

#### 確認状態（棚卸・都度確認）

| 状態 | ラベル | 表示方針 |
|------|--------|----------|
| 確認済 | 確認済 | 成功色 |
| 確認依頼中 | 確認依頼中 | 情報色 |
| 未回答 | 未回答 | 警告色 |
| 差戻し | 差戻し | 警告色 |
| 要是正 | 要是正 | 危険色 |
| 廃止候補 | 廃止候補 | グレー |

#### リスク重大度

| 重大度 | ラベル | 表示方針 |
|--------|--------|----------|
| Critical | 緊急 | 危険色（強） |
| High | 高 | 危険色 |
| Medium | 中 | 警告色 |
| Low | 低 | 情報色 |
| Info | 情報 | グレー |

#### 管理情報設定区分

| 区分 | ラベル | 表示方針 |
|------|--------|----------|
| 個別設定 | 個別 | 通常表示 |

| 暫定設定 | 暫定 | 警告色。全社ドメイン管理部門が暫定責任 |

### 3-3. 参照範囲共通ルール

| ロール | ドメイン・履歴・棚卸の参照範囲 |
|--------|--------------------------------|
| システム管理者 / ドメイン管理責任者 / 管理担当者 | 全管理対象・全監視対象 |
| 経営層 / IT資産管理担当者 | 全管理対象（参照中心） |
| ドメイン利用部門 | 自部門が管理責任部署となっている管理単位 |
| 知財・ブランド管理 | 監視対象・知財ブランド保護情報を全件、管理対象は参照 |
| DNS・インフラ運用 | DNS 管理情報・証明書を全件、管理対象は参照 |
| セキュリティ運用 | セキュリティ対策状況・リスク・インシデントを全件、管理対象は参照 |

## 4. SC-01: ダッシュボード

### 表示項目

| 領域 | 表示内容 |
|------|----------|
| ページヘッダー | タイトル、最終バッチ実行日時（B01〜B05 の最新） |
| サマリー | 管理対象ドメイン数、個別管理対象数、監視対象数、暫定管理責任の件数 |
| 期限接近 | ドメイン更新期限・証明書有効期限の接近件数（30/60/90 日区分） |
| リスク | 未対応リスク件数（重大度別）、テイクオーバー・なりすまし疑い件数 |
| 棚卸 | 確認依頼中・未回答・期限超過・要是正の件数 |
| 承認 | 承認待ち件数、滞留（一定日数超過）件数 |

### 表示制御

- 各カードは対応する一覧画面へ、絞り込み条件付きで遷移する。
- 期限・リスク・棚卸・承認の判定は、対応するバッチ（B07/B08）および機能要件の業務判定と揃える。
- 参照範囲が限定されるロールは、自部門が管理責任を負う範囲のみ集計する。

- 自動収集項目には取得元と最終取得日時を併記する。

- 「承認申請」は承認対象操作（取得・廃止・移管・管理責任者変更・ブランド重要判断）に対してのみ表示する。

## 7. SC-04: ドメイン登録・編集フォーム

### 入力項目（基本）

| 項目 | 種別 | 必須 | 制御 |
|------|------|------|------|
| ドメイン名（FQDN） | text | 必須 | 新規時のみ編集可。FQDN 形式 |
| 種別 | プルダウン | 必須 | gTLD / ccTLD / サブドメイン |
| 管理区分 | プルダウン | 必須 | 管理対象 / 個別管理対象 |
| 対象会社 | プルダウン | 必須 | 自社 / グループ会社 |
| 対象ブランド | プルダウン | 任意 | 有効なブランドマスタ |
| 更新方針 | プルダウン | 任意 | 自動更新 / 手動更新 |
| 取得目的・利用予定 | textarea | 新規取得時必須 | |
| 費用負担 | text | 任意 | |
| セキュリティ方針 | textarea | 任意 | |
| 管理責任部署 | 部署検索 | 任意 | 空の場合は継承 |
| 管理責任者 | 担当者検索 | 任意 | 空の場合は継承 |
| 承認者 | 担当者検索 | 新規取得時必須 | |
| 備考 | textarea | 任意 | |

### 参照・更新範囲

- システム管理者・ドメイン管理担当者は全ドメインを登録・編集できる。
- 利用部門は、自部門が管理責任を負う管理単位の範囲でのみ登録・編集できる。
- 範囲外のドメインを編集しようとした場合は 403 とする。

### バリデーション

- ドメイン名は FQDN 形式で、既存の管理対象と重複しないこと。
- 種別、管理区分、対象会社は必須。
- 新規取得時は取得目的・利用予定・承認者を必須とする。
- 管理責任部署・責任者が空の場合は、責任継承ルールで継承元を解決して表示する。
- 自動収集で補完される項目（有効期限、レジストラ、ネームサーバ等）は手動入力を必須としない。
- 保存エラーはフォーム内に表示し、入力値を保持する。
- 新規登録成功時はステータス `pending` で保存し、変更履歴に新規登録を記録、承認機能（F15）へ引き渡す。

## 8. SC-05: CSV インポート

### 入力項目

| 項目 | 種別 | 必須 |
|------|------|------|
| CSV ファイル | file | 必須 |
| 取込種別 | プルダウン | 必須（ドメイン台帳 / 担当者 / 監視対象） |

### CSV 列（ドメイン台帳の例）

`domain_name, type, mgmt_category, company, brand, renewal_policy, mgmt_dept, mgmt_owner, note`

### バリデーション

- CSV ファイルが未指定の場合はエラーを表示する。
- 各行のドメイン名は FQDN 形式で、既存管理対象および CSV 内で重複しないこと。
- 対象会社・ブランド・部署は有効なマスタに存在すること。
- 1 行でもエラーがある場合、全行を登録しない。
- 登録成功時は各件に変更履歴を記録する。台帳の新規取込はステータス `pending`。

### セキュリティ

- CSV ダウンロード時は、Excel 数式として解釈される値を無害化する。
- 機密情報（証明書秘密鍵、DNS 管理アカウント認証情報等）は取込項目に含めない。

## 9. SC-06: ライフサイクル操作

### 操作種別

| 操作 | 入力項目 | 承認要否 |
|------|----------|----------|
| 利用開始 | DNS 設定、公開先、証明書、メール利用、外部連携、監視対象、担当者情報 | 不要 |
| 更新 | 更新予定 / 完了 / 更新不要判断、費用負担、関係者確認結果 | 不要 |
| 移管 | 移管先（レジストラ／部署／グループ会社／外部委託先）、移管前後の責任者・権限、DNS 影響、証明書影響 | 必要 |
| 廃止 | 利用停止確認、DNS 削除・無効化、証明書失効、メール停止、リダイレクト要否、再取得リスク、ブランドリスク、廃止判断 | 必要 |

### バリデーション・フィードバック

- 移管・廃止は承認機能（F15）に引き渡し、承認完了まで実行を確定しない。
- 各操作は変更内容・変更理由・実施者・実施日時を変更履歴に記録する。
- 廃止時の確認項目（DNS 削除、証明書失効、メール停止等）は確認チェックを必須とする。

## 10. SC-07: 管理責任・継承設定

### 表示・入力項目

| 項目 | 種別 | 内容 |
|------|------|------|
| 管理情報設定区分 | 表示 | 個別設定 / 継承 / 暫定設定 |
| 継承元管理単位 | 表示 | 継承時の親ドメイン／DNSゾーン／サブドメイン名前空間 |
| 個別管理対象化 | チェック | 個別管理対象へ昇格する |
| 個別管理対象化理由 | 複数選択 | NS 委任 / 外部サービス連携 / メール・認証・決済 / ブランド重要性 / 運用部署差異 |
| 管理責任部署 | 部署検索 | 個別設定時に指定 |
| 管理責任者 | 担当者検索 | 個別設定時に指定 |
| 主担当・副担当 | 担当者検索 | 任意 |
| 連絡先 | text | グループメール／チーム連絡先を推奨 |

### バリデーション

- 個別管理対象化する場合、理由を 1 つ以上選択し、管理責任部署を指定すること。
- 個別設定を解除した場合、責任継承ルールで継承元を再解決して表示する。
- 証明書発行・テイクオーバーリスク検知のみを理由とした昇格は選択肢に含めない（リスク・是正で扱う）。
- 連絡先は個人メールより、グループメール／チーム連絡先を推奨する旨を表示する。

| 対象管理単位 | ドメイン / DNSゾーン / サブドメイン名前空間 |
| 管理責任部署 | 部署名 |
| 棚卸種別 | 定期棚卸 / 都度確認 |
| 依頼日 | 依頼日 |
| 確認状態 | 確認済 / 確認依頼中 / 未回答 / 差戻し / 要是正 / 廃止候補 |
| 次回確認期限 | 期限（超過は強調） |
| 操作 | 回答・確認 |

### SC-08 検索・絞り込み

- 管理単位、管理責任部署、棚卸種別、確認状態、期限超過有無で絞り込めること。
- 利用部門は自部門が管理責任を負う管理単位のみ表示する。
- 未回答・期限超過の絞り込みを既定で用意する。

### SC-09 表示・入力項目

| 領域 | 内容 |
|------|------|
| 確認対象 | 保有状況、利用状況、管理部署、管理責任者、担当者、更新要否、セキュリティ対策状況、外部サービス連携状況 |
| 自動検知差分 | 前回棚卸以降にバッチが検知した差分（用途変化、DNS 変更、外部連携変化等） |
| 回答 | 各確認項目の確認結果、変更要否、是正要否、廃止候補判断 |
| コメント | 回答コメント |

### バリデーション・フィードバック

- 自動検知された差分は、確認結果（妥当 / 要修正 / 是正依頼）の回答を必須とする。
- 要是正と回答した場合、リスク・是正対応（F09）に起票する。
- 回答完了で確認状態を「確認済」に更新し、最終棚卸日・次回確認期限を更新する。
- 差戻し時は理由を記録し、確認状態を「差戻し」とする。
- 個別管理対象でないサブドメインは、上位管理単位の棚卸に代表確認として含め、全件個別回答を求めない。

## 17. SC-20 / SC-21: 承認

### SC-20 表示項目

| 列 | 内容 |
|----|------|
| 申請日時 | 申請日時 |
| 申請者 | 申請者氏名 |
| 承認種別 | 新規取得 / 廃止 / 管理責任者変更 / レジストラ移管 / ブランド重要判断 |
| 対象ドメイン | FQDN |
| 概要 | 申請概要 |
| 滞留 | 一定日数超過の強調 |
| 操作 | 詳細・処理 |

### 参照範囲

- システム管理者・ドメイン管理責任者は全社の承認申請を表示する。
- ブランド重要判断は、知財・ブランド管理担当者の確認・否認証跡を要する申請として表示する。
- その他のロールは参照できない。

### SC-21 操作

| 操作 | 仕様 |
|------|------|
| 承認 | 申請内容を確定し、対象ドメインのステータス・管理情報を更新 |
| 否認 | 理由コメント必須。申請を差し戻す |

### バリデーション・フィードバック

- 承認権限がない申請への GET / POST は 403 とする。
- 否認コメントは必須。未入力時は詳細画面内へエラーを表示し、申請状態を保持する。
- 承認・否認の結果と証跡を変更履歴に記録する。
- htmx POST の場合、承認待ち件数バッジとトーストを OOB 更新する。
- htmx POST には `X-CSRFToken` ヘッダーを付与する。

## 18. SC-22: マスタ・権限管理

### 表示・権限制御

- システム管理者のみがアクセスできる。非該当ロールは 403、未ログインは `/login/` へリダイレクトする。
- ロール（グループ）と利用者の割当を管理できる。
- 部署・担当者マスタ、対象会社・ブランド、管理単位、監視対象キーワード、通知設定を管理できる。
- 組織・社員・所属情報は外部連携（B09）の同期結果を表示し、手動メンテナンスを併用する。

### 操作の制約

- 状態変更（権限付与・剥奪、マスタ更新）は POST かつ CSRF トークンを必須とする。
- 連絡先は個人メールではなくグループメール／チーム連絡先を推奨する旨を表示する。
- 機密情報そのもの（認証情報・秘密鍵）はマスタ項目に含めず、保管先・管理責任者のみを管理する。

---

## 19. SC-23: 利用方法

- ドメイン登録、ライフサイクル操作、棚卸回答、リスク是正、承認、監視対象確認への運用ガイドを表示する。
- ロールにより利用できない機能への導線は、非表示または権限が必要であることを明示する。

## 20. 共通バリデーション・エラー表示

| 項目 | ルール |
|------|--------|
| 必須項目 | 未入力時は項目直下にエラーを表示 |
| ドメイン名 | FQDN 形式であること、管理対象内で一意であること |
| 日付 | 有効な日付形式であること |
| 日時 | 有効な datetime-local 形式であること |
| 終了日 / 終了予定日 | 開始日 / 開始予定日以降であること |
| マスタ参照 | 有効な会社・ブランド・部署・担当者・管理単位のみ選択可能 |
| 機密情報 | 認証情報・秘密鍵そのものは入力・保存しない |
| 権限外操作 | 403 を返す |
| 保存成功 | メッセージまたはトーストを表示 |
| htmx 部分更新 | 対象領域のみ更新し、必要に応じて OOB でバッジ・トーストを更新 |

## 21. アクセシビリティ・表示品質

- 操作ボタンは意味の分かるラベルを持つこと。
- 状態・リスク重大度・確認状態は色だけに依存せず、テキストラベルも表示すること。
- 自動収集された情報は、手動入力された情報と区別がつくよう取得元・取得日時を明示すること。
- テーブルは列見出しを明示し、ソート可能列は視覚的に分かること。
- エラーメッセージは対象フィールドの近くに表示すること。
- トーストや成功メッセージは、処理結果が分かる文言にすること。
