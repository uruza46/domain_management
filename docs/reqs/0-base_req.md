# 0. 基本要件

## 0.1 背景
企業で保有するドメインは、ブランド保護やセキュリティ対策の観点から、適切な管理が求められる重要なIT資産である。しかし、ドメイン管理は属人的な運用に依存しがちで、管理者の異動や退職による情報の陳腐化、更新漏れによるドメイン失効リスク、意図せぬドメインキャッチやサブドメインテイクオーバーなどのセキュリティリスクが存在する。また、ドメインの用途や管理ルールが不明確な場合、ブランド毀損リスクのある利用や用途外利用が発生する可能性もある。さらに、ドメイン管理と他のIT資産管理との連携が不十分な場合、全体的なIT資産管理の効率性や効果性が低下する。

## 0.2 目的
以下の課題を解決するため、できる限り属人的且つ人手による運用を排除し、ドメイン管理の全体像を可視化・体系化するドメイン管理システムを構築することを目的とする。
また、そのために必要な情報収集を自動化することで、役立つ情報を適切なタイミングで関係者に提供し、本システムの管理を含め、各担当者の負担を可能な限り極小化する。これにより、ドメイン管理の効率性と効果性を向上させ、形骸化しにくいドメイン管理体制を構築する。

### 0.2.1 主な課題
1. 意図せぬドメインキャッチ
2. サブドメインテイクオーバー
3. ドメインの不適切な利用
4. ドメインのセキュリティ対策の不備
5. ドメインの更新漏れ・失効リスク
6. ドメイン管理者・管理ルールの不在または不明確さ
7. ドメイン（サブ含む）の管理組織・管理者情報の陳腐化
8. 一部のドメイン階層が深くなりすぎることによる承認・管理の形骸化
9. IT資産としてのドメイン管理不足
10. 他のIT資産管理との連携不足
11. 全社保有ドメインの把握不足

## 0.3 対象範囲
本システムでは、企業が保有、利用、管理、または管理責任を負う公開ドメインを対象とする。公開ドメインとは、インターネット上で名前解決されるドメインおよびDNSゾーンを指す。

### 0.3.1 管理対象ドメイン
以下を管理対象とする。

1. 自社またはグループ会社が登録者、管理者、利用者となっているドメイン
2. 事業、サービス、製品、キャンペーン、採用、広報等で利用するドメイン
3. ブランド保護、商標保護、類似名称対策等を目的として保有するドメイン
4. 利用停止中、リダイレクト用、パーキング中など、現在は主要用途がないが保有を継続しているドメイン

自社ブランド名、サービス名、商標、略称等を含み、会社として把握・監視すべき候補ドメインは、管理対象ではなく監視対象として扱う。監視対象については、保有・利用・契約・DNS管理情報等を必須管理項目とはせず、検知結果、確認状況、対応判断、対応履歴を管理する。

サブドメインについては、検知できたものを原則として管理対象に含め、親ドメインまたは上位サブドメイン名前空間から管理部署・管理責任者等の管理情報を継承する。ただし、個別の管理部署・管理責任者を設定する対象とするかどうかは、0.4.3 の個別管理対象への昇格条件に基づき判断する。

### 0.3.2 対象外範囲
以下は原則として対象外とする。ただし、公開ドメインのリスク評価や管理に必要な場合は、参照情報として取り扱う。

1. 社内ネットワーク専用の内部ドメインおよびプライベートDNSゾーン
2. 端末、サーバ、ネットワーク機器等の詳細な資産管理
3. Webサイト、アプリケーション、メールシステム等の詳細な構成管理
4. 証明書秘密鍵、DNS管理アカウントの認証情報などの機密情報そのものの保管
5. 法務判断、商標出願、係争対応等の専門業務そのもの

個別管理対象への昇格は、原則としてFQDN単位ではなく、DNSゾーンまたはサブドメイン名前空間単位で行う。これにより、個別管理対象の件数増加を抑制し、管理責任の境界を明確に保つ。

## 0.4 利用者・関係者
以下を主な利用者・関係者とする。必要に応じて追加・変更する可能性がある。

| 区分 | 主な役割 |
| --- | --- |
| ドメイン管理責任者 | 全社ドメイン管理方針の決定、承認、重要リスクの判断を行う。 |
| ドメイン管理担当者 | ドメイン台帳の維持、棚卸、更新確認、関係者調整を行う。 |
| ドメイン利用部門 | ドメインの利用目的、利用状況、担当者情報を管理する。 |
| 知財・ブランド管理担当者 | 商標、ブランド保護、類似ドメイン監視に関する確認を行う。 |
| DNS・インフラ運用担当者 | DNS設定、ネームサーバ、DNSSEC等の技術情報を確認・更新する。 |
| セキュリティ運用担当者 | セキュリティ対策状況、脆弱性、悪用リスク、是正状況を確認する。 |
| IT資産管理担当者 | 他のIT資産情報との整合性確認、資産管理台帳との連携を行う。 |
| 経営層・マネジメント層 | 重要リスク、未対応事項、全体状況の報告を受ける。 |

### 0.4.1 管理責任の基本方針
本システムでは、全てのドメインおよびサブドメインに対して個別に管理部署・管理責任者を設定するのではなく、登録ドメイン、DNSゾーン、サブドメイン名前空間などの責任境界を管理単位とする。

サブドメインは、個別の管理責任が設定されていない限り、最も近い上位の管理単位から管理部署・管理責任者を継承する。これにより、数万件規模のサブドメインが存在する場合でも、中央管理部門が全件を直接管理するのではなく、責任境界ごとに実運用部門へ管理責任を委譲できるようにする。

### 0.4.2 管理責任の継承ルール
管理部署・管理責任者は、以下の優先順位で決定する。

1. 対象ドメインまたはサブドメインに個別の管理部署・管理責任者が設定されている場合は、その設定を優先する
2. 個別設定がない場合は、最も近い上位のサブドメイン名前空間の管理部署・管理責任者を継承する
3. 上位サブドメイン名前空間にも設定がない場合は、親ドメインの管理部署・管理責任者を継承する
4. 親ドメインにも設定がない場合は、全社ドメイン管理部門を暫定的な管理責任部署とする

### 0.4.3 個別管理対象への昇格条件
以下に該当するサブドメインまたはサブドメイン名前空間は、親からの継承ではなく、個別の管理部署・管理責任者を設定する対象とする。

1. NS委任されている
2. 外部SaaS、クラウドサービス、CDN、ホスティングサービス等へCNAMEまたは同等の設定で連携している
3. メール、認証、決済等で利用している
4. ブランド、商標、製品、サービス、キャンペーン等の観点で重要である
5. 親ドメインの管理部署とは異なる部署が実質的に運用責任を持っている

証明書が発行されていること、またはサブドメインテイクオーバー等のリスクが検知されていることのみを理由として、自動的に個別管理対象へ昇格させることは初期範囲では行わない。これらはリスク確認・通知・是正対応の対象として扱い、個別管理対象への昇格要否は必要に応じて判断する。

## 0.5 管理対象情報
本システムでは、ドメインの所有・利用・運用・リスク・責任者を継続的に把握できる情報を管理する。
また、これらの情報に関する変更履歴や自動収集した情報の変更履歴を記録（変更がない間の情報はできる限り圧縮）し、いつ、誰が、何を、なぜ変更したかを追跡できるようにする。

### 0.5.1 ドメイン基本情報
ドメイン名、種別、状態、登録日、有効期限、更新方針、管理区分、対象会社、対象ブランド、備考を管理する。
※自動取得可能な主な項目は以下の通り。
- ドメイン名：ドメインの完全修飾ドメイン名（FQDN）を管理する。
- 種別：ドメインの種別（例：gTLD、ccTLD、サブドメインなど）を管理する。
- 状態：ドメインの状態（例：active、expired、pending、deletedなど）を管理する。
- 登録日：ドメインの登録日を管理する。
- 有効期限：ドメインの有効期限を管理する。
- 更新方針：ドメインの更新方針（例：自動更新、手動更新など）を管理する。

### 0.5.2 レジストラ・契約情報
レジストラ名、契約名義、契約管理部署、契約更新方式、支払担当、移管可否、更新期限、更新通知先を管理する。
※自動取得可能な主な項目は以下の通り。
- レジストラ名：ドメインを登録しているレジストラの名称を管理する。
- 契約名義：ドメインの登録者名義を管理する。通常は企業名や組織名が登録されるが、個人名義の場合もあるため、登録情報を正確に管理することが重要である。
- 更新期限：ドメインの更新期限を管理する。ドメインの有効期限と同様に、更新期限も自動取得することで、更新漏れリスクを低減することができる。
- 更新通知先：ドメインの更新期限が近づいた際に通知を送る対象のメールアドレスや担当者を管理する。これも自動取得することで、更新漏れリスクを低減することができる。

### 0.5.3 DNS管理情報
ネームサーバ、DNS管理サービス、DNSゾーン管理者、主要レコード、DNSSEC設定状況、SPF/DKIM/DMARC等のメール関連設定状況を管理する。
※自動取得可能な主な項目は以下の通り。
- ネームサーバ：ドメインのDNSレコードを管理するネームサーバの情報を管理する。通常は、ドメインの登録情報から自動取得することができる。
- DNS管理サービス：ドメインのDNSレコードを管理するために利用しているDNS管理サービスの情報を管理する。これもドメインの登録情報から自動取得することができる場合が多いが、複数のDNS管理サービスを利用している場合や、レジストラとは別のDNS管理サービスを利用している場合は、手動で管理する必要がある。
- 主要レコード：ドメインの利用状況やリスク評価に必要なDNSレコードの情報を管理する。例えば、Webサイト公開に利用しているAレコードやCNAMEレコード、メール利用に関連するMXレコードやSPFレコードなどが該当する。これらの情報は、ドメインの登録情報から自動取得できる場合もあるが、複数のDNS管理サービスを利用している場合や、レジストラとは別のDNS管理サービスを利用している場合は、手動で管理する必要がある。
- DNSゾーン管理者：ドメインのDNSゾーン管理者の情報を管理する。通常は、ドメインの登録情報から自動取得することができるが、DNSゾーン管理者は、DNS設定の変更やトラブル対応に関する管理責任を持つ担当者であり、ネームサーバやDNS管理サービスなどの自動取得情報とは別に管理することが望ましい。DNSゾーン管理者は、ドメインのDNS設定に関する問い合わせや変更依頼の窓口となるため、正確な情報を管理することが重要である。

### 0.5.3.1 DNSゾーン管理者情報
広域なサブドメイン名前空間を管理する場合は、DNSゾーン管理者を設定することができるようにして、DNS管理情報の管理負担を分散することができるようにする。

### 0.5.4 用途管理情報
利用目的、利用サービス、公開サイト、メール利用有無、リダイレクト有無、外部サービス連携有無、利用開始日、利用終了予定日を管理する。

### 0.5.5 知財・ブランド保護情報
知財・ブランド保護観点が必要なドメインについての承認・否認に関する証跡情報及び、関連サービスとの紐付きを管理する。
また、将来的には関連ブランド、関連商標、保護目的、類似ドメインとの関係、取得理由、保有継続理由、ブランドリスク等の自動評価も実施することを検討する。

### 0.5.6 セキュリティ対策状況
DNSSEC、レジストリロック、レジストラロック、MFA、権限管理、サブドメインテイクオーバー対策、期限切れ証明書対策、メールなりすまし対策等の実施状況を管理する。
※自動取得・チェック可能な主な項目は以下の通り。これらの情報をもとに、セキュリティリスクの自動評価や是正対応の優先順位付けを行うことも検討する。
- DNSSEC設定状況：DNSゾーンに対してDNSSECが設定されているかどうかを確認する。
- レジストリロック・レジストラロック状況：ドメインがレジストリロックやレジストラロックされているかどうかを確認する。
- MFA設定状況：レジストラアカウントに対して多要素認証が設定されているかどうかを確認する。
- サブドメインテイクオーバー対策状況：ドメインのサブドメインに対して、サブドメインテイクオーバーのリスクがある設定（例：CNAMEで外部サービスと連携しているが、外部サービス側で設定が削除されている等）がないかどうかを確認する。
- 期限切れ証明書対策状況：ドメインに対して発行されている証明書の有効期限が切れていないかどうかを確認する。
- メールなりすまし対策状況：ドメインに対して、SPF、DKIM、DMARCなどのメールなりすまし対策が設定されているかどうかを確認する。

### 0.5.7 証明書情報
証明書の発行先ドメイン、発行者、有効期限、発行方式、更新方式、利用システム、管理担当（ML可）、失効予定、CTログ検知結果を管理する。
※自動取得可能な主な項目は以下の通り。
- 証明書の発行先ドメイン：証明書が発行されているドメインを管理する。通常は、証明書のサブジェクトやSANフィールドから自動取得することができる。
- 証明書の発行者：証明書を発行した認証局の情報を管理する。これも証明書の情報から自動取得することができる。
- 証明書の有効期限：証明書の有効期限を管理する。これも証明書の情報から自動取得することができる。
- 証明書の発行方式：証明書がどのような方式で発行されたかを管理する。例えば、ACMEプロトコルを使用して自動発行された証明書、手動で発行された証明書、外部委託先が発行した証明書などが該当する。これらの情報は、証明書の情報から自動取得できる場合もあるが、発行方式は必ずしも証明書の情報から自動取得できるわけではないため、手動で管理する必要がある場合もある。
- 証明書の更新方式：証明書の更新方式を管理する。例えば、自動更新、手動更新、外部委託先が更新するなどが該当する。これも証明書の情報から自動取得できる場合もあるが、更新方式は必ずしも証明書の情報から自動取得できるわけではないため、手動で管理する必要がある場合もある。

### 0.5.8 担当部署・担当者情報
主管部署、利用部署、技術担当、承認者、代理担当、連絡先、担当変更履歴、最終確認日を管理する。

責任継承モデルを実現するため、以下の情報を管理する。

- 管理情報設定区分：個別設定、継承、暫定設定のいずれであるかを管理する。
- 継承元管理単位：継承している親ドメイン、DNSゾーン、サブドメイン名前空間を管理する。
- 個別管理対象化理由：NS委任、外部サービス連携、メール・認証・決済利用、ブランド重要性、運用部署差異等の理由を管理する。
- 管理責任部署：対象の管理責任を負う部署を管理する。
- 管理責任者：対象の管理責任を負う責任者を管理する。
- 主担当・副担当：実務上の問い合わせ、棚卸回答、是正対応を行う担当者を管理する。
- 連絡先：個人メールではなく、可能な限りグループメールまたはチーム連絡先を管理する。
- 最終棚卸日：直近の定期棚卸または都度確認が完了した日を管理する。
- 次回確認期限：次回の定期棚卸または確認期限を管理する。
- 確認状態：確認済、確認依頼中、未回答、差戻し、要是正、廃止候補等の状態を管理する。

### 0.5.9 インシデント・トラブル情報
過去のインシデントやトラブルの情報を管理する。これには、インシデントの発生日時、内容、影響範囲、対応状況、再発防止策などが含まれる。これらの情報は、ドメインのリスク評価や是正対応の優先順位付けに活用することができる。

## 0.6 ドメインライフサイクル
ドメインは、取得から廃止までの各段階で必要な情報、承認、確認、記録を管理する。

### 0.6.1 取得・登録
新規取得時は、取得目的、利用予定、関連ブランド、管理責任者、費用負担、セキュリティ方針、承認者を登録する。

### 0.6.2 利用開始
利用開始時は、DNS設定、公開先、証明書、メール利用、外部サービス連携、監視対象、担当者情報を登録する。

### 0.6.3 変更
用途、担当者、DNS設定、レジストラ、証明書、外部委託先等に変更があった場合は、変更内容、変更理由、実施者、承認者、実施日時を記録する。

DNS設定変更は、原則として対象ドメインまたはサブドメインを利用するドメイン利用者または該当管理部署の責任で行う。本システムではDNS設定変更に対する事前承認を必須とはせず、自動検知または申告に基づき、変更内容の事後確認、差分記録、必要な是正依頼を行う。

### 0.6.4 更新
有効期限前に更新要否を確認し、更新予定、更新完了、更新不要判断、費用負担、関係者確認結果を記録する。

### 0.6.5 移管
レジストラ、管理部署、グループ会社、外部委託先等の変更に伴う移管を管理し、移管前後の責任者、権限、DNS影響、証明書影響を記録する。

### 0.6.6 廃止
廃止時は、利用停止確認、DNS削除・無効化、証明書失効、メール停止、リダイレクト要否、再取得リスク、ブランドリスクを確認し、廃止判断を記録する。

## 0.7 管理業務
ドメイン管理担当者は、台帳の正確性とリスク状況を維持するため、以下の業務を行う。

### 0.7.1 台帳管理
管理対象ドメインの基本情報、利用情報、担当者情報、リスク情報を一元管理し、最新状態を維持する。

### 0.7.2 棚卸
管理対象ドメインおよび個別管理対象のサブドメイン名前空間について、原則として年1回の定期棚卸を実施する。棚卸では、保有状況、利用状況、管理部署、管理責任者、担当者、更新要否、セキュリティ対策状況、外部サービス連携状況を確認する。

個別管理対象ではないサブドメインについては、親ドメイン、DNSゾーン、または上位サブドメイン名前空間の棚卸に含めて代表確認する。全件に個別回答を求めるのではなく、自動検知された差分、リスク、用途変化、外部サービス連携変化など、確認が必要なものを都度確認の対象とする。

定期棚卸とは別に、管理対象情報、管理部署、管理責任者、担当者、用途、DNS設定、外部サービス連携、契約・更新情報等に変更があった場合は、関係する管理部署または管理責任者に都度確認を依頼する。

棚卸および都度確認の依頼、回答状況、確認結果、未回答、差戻し、是正要否は記録し、未回答または期限超過の場合は通知・エスカレーションの対象とする。

### 0.7.3 利用状況確認
Web公開、メール利用、DNSレコード、外部サービス連携、証明書利用状況を自動的に確認し、台帳情報との差異を検出する。

### 0.7.4 リスク確認
失効リスク、設定不備、サブドメインテイクオーバーリスク、なりすましリスク、ブランド毀損リスク、担当者不在リスクを確認する。

### 0.7.5 是正対応管理
検出された不備やリスクについて、対応方針、担当者、期限、対応状況、完了確認結果を管理する。

## 0.8 権限・承認
利用者の役割に応じて、閲覧、登録、変更、承認、削除、是正完了確認の権限を制御する。

新規取得、廃止、管理責任者変更、レジストラ移管、ブランド保護上重要な判断については、承認を必要とする。

DNS設定変更は、ドメイン利用者または該当管理部署の責任範囲として扱い、本システム上の事前承認対象には含めない。検知したDNS設定変更については、必要に応じて事後確認、通知、是正対応の対象とする。

## 0.9 通知・アラート
以下の事象について、関係者に通知またはアラートを行う。

1. ドメイン更新期限の接近
2. 証明書有効期限の接近
3. 担当者未設定または担当者情報の陳腐化
4. DNS設定の不整合または危険な設定
5. サブドメインテイクオーバーの可能性
6. DNSSEC、DMARC等の重要対策の未設定
7. 類似ドメイン、なりすまし、ブランド毀損につながる可能性の検知
8. 棚卸未回答、是正期限超過、承認滞留

## 0.10 監査・履歴
ドメイン情報、担当者情報、DNS関連情報、承認状態、リスク評価、是正対応の変更履歴を記録する。

監査時には、いつ、誰が、何を、なぜ変更したかを確認できること。また、過去時点の担当者、利用目的、承認状態、リスク状態を追跡できること。

## 0.11 外部連携
必要に応じて、以下の外部サービスまたは社内システムと連携する。

1. レジストラまたはドメイン管理サービス
2. DNS管理サービス
3. 証明書管理サービスおよびCTログ監視
4. IT資産管理システム
5. ID管理・組織マスタ・社員マスタ・所属情報
6. ワークフロー・承認システム
7. メール、チャット、チケット管理システム
8. セキュリティ診断・ASM・脆弱性管理サービス

初期段階では、すべての外部連携を必須とせず、手動登録、CSV取込、定期バッチ、自動API連携を段階的に選択できるものとする。

## 0.12 非機能・制約
本システムは、全社の公開ドメイン管理に必要な可用性、保全性、監査性、操作性を備えること。

1. 管理情報の正確性を維持するため、入力必須項目、更新期限、未確認状態を管理できること
2. 権限に応じて、閲覧・編集できる情報を制御できること
3. 監査証跡を保持し、必要に応じて出力できること
4. 更新期限、証明書期限、棚卸期限などの重要期限を見落としにくいこと
5. 初期導入時は過度に複雑な運用を求めず、段階的に管理精度を高められること
6. 機密情報そのものは保持せず、必要に応じて保管先や管理責任者のみを管理すること
7. データのバックアップとリストアが可能であること
8. システムの障害や不具合が発生した場合に可能な限り自動復旧できること
9. システムの利用状況やパフォーマンスを監視できること
10. システムの利用者が適切に利用できるよう、操作マニュアルやヘルプ機能を提供すること

## 0.13 用語

### 0.13.1 一般用語
| 用語 | 説明 |
| --- | --- |
| 公開ドメイン | インターネット上で名前解決されるドメインまたはDNSゾーン。 |
| FQDN | Fully Qualified Domain Name の略。ドメイン名を省略せず完全な形で表した名前。 |
| ドメインキャッチ | 失効したドメインが第三者に取得されること。 |
| サブドメインテイクオーバー | 不要なDNS設定や外部サービス設定の残存により、第三者がサブドメインを悪用可能になる状態。 |
| DNSSEC | DNS応答の正当性を検証するための仕組み。 |
| CTログ | TLS証明書の発行履歴を確認できる公開ログ。 |
| レジストラロック | 不正な移管や変更を防ぐため、レジストラ側でドメインをロックする仕組み。 |
| レジストリロック | レジストリ側でドメインの重要変更を制限する高強度の保護設定。 |
| DMARC | メールなりすまし対策のため、SPF/DKIMの認証結果に基づく取り扱い方針を宣言する仕組み。 |
| SPF | メール送信元の正当性を検証するためのDNSレコード。 |
| DKIM | メールの改ざんを検出するため、メールに電子署名を付与する仕組み。 |

### 0.13.2 内部用語
| 用語 | 説明 |
| --- | --- |
| 管理対象 | 本システムで把握、記録、監視、確認の対象とするドメインまたはサブドメイン。サブドメインは検知できたものを原則として管理対象に含める。 |
| 個別管理対象 | 親ドメインまたは上位サブドメイン名前空間からの継承ではなく、個別の管理部署・管理責任者を設定する対象。 |
| 監視対象 | 自社が保有または利用しているとは限らないが、ブランド、商標、なりすまし等の観点で継続的に確認する対象。 |
| 管理単位 | 管理部署・管理責任者・棚卸・通知等を設定する単位。登録ドメイン、DNSゾーン、サブドメイン名前空間などを指す。 |
| 責任境界 | どの部署または責任者が管理責任を負うかを分ける境界。 |
| 継承 | 個別管理対象でないサブドメインが、親ドメインまたは上位サブドメイン名前空間の管理情報を引き継ぐこと。 |
| 暫定管理責任部署 | 親側にも管理情報がない場合に、一時的に管理責任部署として扱う全社ドメイン管理部門。 |

## 0.14 検討事項
以下は後続要件で具体化する。

1. 管理対象に含めるグループ会社、海外法人、関連会社の範囲
2. サブドメインをどの粒度まで台帳管理するか
3. 類似ドメイン監視の対象キーワード、監視頻度、対応フロー
4. DNS情報、証明書情報、レジストラ情報の自動収集範囲
5. 新規取得・廃止・移管時の承認者と承認条件
6. リスク評価のスコアリング方法
7. 既存IT資産管理システムとの連携範囲
8. 初期導入時に必須とする項目と、将来拡張とする項目
