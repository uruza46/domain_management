# クラウドデプロイ要件

*作成日: 2026/06/05 ／ 親: [3-nonfunc_req.md](3-nonfunc_req.md)*

---

## 1. 目的

ドメイン管理システムをローカル Docker Compose 開発環境からクラウドへデプロイ可能にする。本番は **AWS ECS Fargate 構成**を基本とし、Web サービスと定期実行バッチ（自動収集・通知）を運用する。

技術スタックは [88-tec_stack.md](88-tec_stack.md) に定義する。コンテナ化・gunicorn・WhiteNoise・Terraform の規律は picsy プロジェクトと共通とし、`terraform/aws/` の実装パターンを参照・再利用する。

---

## 2. AWS 構成（ECS Fargate）— 本番環境

`terraform/aws/` で管理する。

### 2-1. 構成コンポーネント

| コンポーネント | サービス | 備考 |
|---|---|---|
| コンテナ実行 | ECS Fargate | `domain-mgmt-cluster` / `domain-mgmt-web` サービス |
| ロードバランサ | ALB（Application Load Balancer） | HTTP 80番・接続元 IP 制限あり |
| CDN / HTTPS | CloudFront | HTTPS 終端、ドメイン固定（`*.cloudfront.net`） |
| DB | RDS PostgreSQL 16（Single-AZ, db.t4g.micro） | `domain-mgmt-db` |
| コンテナレジストリ | ECR | `domain-management` リポジトリ |
| バッチ実行 | ECS Scheduled Task（Fargate） | Web と同一 image をコマンド上書きで実行 |
| バッチ起動 | EventBridge Scheduler | 各バッチを cron で ECS RunTask 起動 |
| Secret 管理 | AWS Secrets Manager | `DATABASE_URL` / `DJANGO_SECRET_KEY` / 外部 API 認証情報 |
| IaC | Terraform 1.6 以上 | state は S3 backend |

### 2-2. アプリケーション本番実行要件

| 項目 | 要件 |
|------|------|
| HTTP サーバ | Gunicorn（Django `runserver` は本番利用しない） |
| 静的ファイル | Docker build 時 `collectstatic`、WhiteNoise で配信 |
| 本番設定 | `DJANGO_DEBUG=False` |
| 許可ホスト | `DJANGO_ALLOWED_HOSTS`（CloudFront ドメイン） |
| CSRF trusted origins | `DJANGO_CSRF_TRUSTED_ORIGINS`（`https://<cloudfront_domain>`） |
| SECRET_KEY | AWS Secrets Manager から ECS タスク定義で注入 |
| DATABASE_URL | AWS Secrets Manager から ECS タスク定義で注入 |
| マイグレーション | デプロイ時に `python manage.py migrate --no-input` を ECS RunTask（一回限りタスク）で実行 |

### 2-3. バッチ（ECS Scheduled Task + EventBridge Scheduler）

Web と同一の Docker image を使用し、ECS タスク定義の `command` 上書きで各バッチを実行する。EventBridge Scheduler が cron で ECS RunTask を起動する。

| バッチID | 起動スケジュール（JST） | 実行コマンド |
|----------|------------------------|--------------|
| B06 ライフサイクル状態自動遷移 | 毎日 01:00 | `python manage.py run_lifecycle_update` |
| B01 WHOIS・登録情報収集 | 毎日 02:00 | `python manage.py collect_whois` |
| B02 DNS 情報収集 | 毎日 02:30 | `python manage.py collect_dns` |
| B03 証明書・CT ログ監視 | 毎日 03:00 | `python manage.py collect_ct_logs` |
| B04 セキュリティ対策状況チェック | 毎日 03:30 | `python manage.py check_security_status` |
| B09 組織・社員・所属・IT資産マスタ同期 | 毎日 03:00 | `python manage.py sync_masters` |
| B08 棚卸起票・督促 | 毎日 09:30 / 年次 | `python manage.py run_inventory` |
| B07 通知・アラート送信 | 毎日 09:00 | `python manage.py send_notifications` |
| B05 類似・なりすましドメイン監視 | 毎週月曜 04:00 | `python manage.py scan_similar_domains` |
| B10 監査ログエクスポート | 毎月 1 日 01:30 | `python manage.py export_audit_log` |

- EventBridge Scheduler は JST（Asia/Tokyo）で設定する（タイムゾーン指定可）。
- バッチは冪等であり、リトライ設定で失敗時に再実行しても二重処理にならない（[1.2-batch_req.md](1.2-batch_req.md) 14）。
- 実行順序の依存（B01→B02→B03→B04→B06→B08→B07）はスケジュール時刻のオフセットで担保し、長時間化する場合は前段完了を確認するガードを設ける。

### 2-4. Terraform 変数（主要）

| 変数 | 用途 |
|------|------|
| `cloudfront_enabled` | `false` にすると CloudFront が 503 を返す（停止時） |
| `alb_dns_for_cf` | CloudFront オリジン ALB DNS 名（ECS 再作成時に更新が必要） |
| `allowed_hosts` | `DJANGO_ALLOWED_HOSTS` に設定する値 |
| `django_csrf_trusted_origins` | `DJANGO_CSRF_TRUSTED_ORIGINS` に設定する値 |
| `allowed_cidr_blocks` | ALB セキュリティグループの接続元 IP 制限 |
| `egress_allowlist` | 自動収集が外部接続する許可先（WHOIS / DNS / CT / 連携 API） |

## 3. ローカル開発環境（Docker Compose）

`docker-compose.yml` で `web` / `db`（PostgreSQL 16）/ `adminer` を起動する（[99-file_structure.md](99-file_structure.md) 参照）。

```bash
cp .env.example .env
docker compose up -d
docker compose exec web python manage.py migrate
docker compose exec web python manage.py seed_data

# http://localhost:8000  → ドメイン管理システム
# http://localhost:8080  → Adminer（DB確認）
```

- ローカルではバッチを `docker compose exec web python manage.py <command>` で手動実行できる。
- ローカル開発では実ネットワークへの自動収集を行わず、スタブ／フィクスチャを使用できる構成とする。

---

## 4. デプロイ手順要件

1. Docker image を build し、ECR へ push する。
2. Terraform で ECS / ALB / CloudFront / RDS / ECR / Secrets Manager / EventBridge Scheduler / IAM を作成する。
3. AWS Secrets Manager に `DATABASE_URL` / `DJANGO_SECRET_KEY` / 外部 API 認証情報を登録する。
4. ECS RunTask（一回限り）で `migrate` を実行する。
5. `domain-mgmt-web` サービスをデプロイし、ターゲットが healthy になることを確認する。
6. CloudFront を有効化し、オリジン（ALB DNS）が最新であることを確認する。
7. EventBridge Scheduler（B01〜B10）が登録され、ECS Scheduled Task を起動できることを確認する。

---

## 5. 検証要件

クラウド関連の変更は、少なくとも以下を満たすこと。

| 検証 | 合格条件 |
|------|------|
| Docker build | 本番 Dockerfile で image build が成功し、`collectstatic` が成功する |
| Django env smoke | `DJANGO_DEBUG=False`, `DJANGO_SECRET_KEY`, `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS` が settings に反映される |
| Terraform fmt | `terraform fmt -check -recursive` が成功する |
| Terraform init | `terraform init -backend=false` が成功する |
| Terraform validate | `terraform validate` が `Success! The configuration is valid.` を返す |
| ECS Scheduled Task | 各バッチコマンドが ECS RunTask として実行でき、冪等に再実行できる |
| Scheduler | EventBridge Scheduler が JST で各バッチを起動する |
| Django tests | `docker compose run --rm web pytest -v` が成功する |

## 6. コスト節約：一時停止・再開

| フェーズ | 手順 | 残存コスト |
|---------|------|-----------|
| 停止 | EventBridge Scheduler 無効化 → CloudFront 無効化 → ECS/ALB 削除 → RDS 停止 | RDS ストレージ + Secrets Manager の最小コスト |
| 再開 | RDS 起動 → ECS 再作成 → CloudFront 有効化 + オリジン更新 → Scheduler 有効化 | フル稼働コスト |

- CloudFront は停止時も削除せず `enabled=false` で無効化する（ドメイン固定のため）。
- バッチは ECS Scheduled Task（実行時のみ課金）であり、EventBridge Scheduler を無効化すれば停止できる。

## 7. 現時点の保留事項

| 項目 | 理由 |
|------|------|
| CI/CD | 手動デプロイで検証し、必要性が明確になってから導入する |
| GCP 構成 | 当面 AWS ECS Fargate を本番とし、GCP 要素は範囲から除外する |
| 外部連携 API の本番接続情報 | 連携先（レジストラ / DNS / IT資産 / 組織・社員・所属マスタ）確定後に Secrets Manager へ登録する |
| 本番ドメイン / 証明書 | 本番 DNS 確定後に CloudFront のドメイン／証明書を設定する |
| ローカル DB から RDS へのデータ移行 | 本番移行フェーズで別途手順化する |
| 大量サブドメイン収集時のタスク分割 | 実データ規模に応じて ECS Scheduled Task の並列度・分割方式を確定する |
